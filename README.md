# Лад — Nutrition & Training Planner

Веб-приложение для личного и семейного планирования питания, тренировок, режима дня и физического прогресса. Объединяет цели, расписание, питание и тренировки, чтобы предлагать реалистичный план с учётом рабочего дня, сна, тренировок и семейных дел. Рассчитано на нескольких пользователей в одной семье (Household): у каждого свои цели и расписание, а меню и закупки можно вести вместе.

Версия **1.1.0**. Название в интерфейсе, вкладке браузера и установленном приложении — «Лад» (где оно хранится и как его поменять: [frontend/DESIGN.md](frontend/DESIGN.md)). История изменений: [CHANGELOG.md](CHANGELOG.md).

## Что умеет

| Раздел | Что внутри |
| --- | --- |

| Расписание | работа, сон, тренировки, матчи, обязательства; когда человек на работе или дома |
| Справочник продуктов | калорийность и БЖУ на 100 г, свои продукты, единицы измерения |
| Нормы и цели | дневные нормы калорий и БЖУ, цель по весу, история веса |
| Питание | записи о приёмах пищи, рецепты |
| План питания на неделю | меню с учётом расписания и тренировок |
| Закупка и готовка | список покупок по плану недели, что и когда готовить |
| Семейное меню | общее планирование при индивидуальных целях |
| Тренировки | тренировочные сессии и отдельные тренировки |
| Фото прогресса | загрузка и просмотр, проверка типа и размера файла |
| Финансы | доходы и расходы, повторяющиеся доходы и обязательные платежи с датами, бюджетный период «от дохода до дохода», оценка финансовой нагрузки, цели (накопления, долги, кредиты с процентами), личные и семейные книги |

| PWA | установка на главный экран, заставка загрузки, своя иконка, офлайн-страница, интерфейс для телефона и компьютера |

## Технологии

- **Backend** (`backend/`): Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x, PostgreSQL 16, Alembic, JWT.
- **Frontend** (`frontend/`): Next.js 16, React 19, TypeScript, Tailwind CSS.
- **Развёртывание** (`deploy/`): Docker Compose, Caddy (автоматический HTTPS), резервные копии по расписанию.

Архитектура backend — модульный монолит: `*_routes.py` принимают HTTP-запросы, `schemas.py` проверяет данные, `*_services.py` содержат бизнес-логику и проверки прав, `models.py` описывает таблицы, `alembic/` хранит историю изменений структуры базы.

## Структура папок

```
backend/            API на FastAPI, модели, миграции, тесты (backend/tests)
frontend/           сайт на Next.js (страницы в frontend/app, запросы к API в frontend/lib)
deploy/             всё для публичного сервера: Caddy, compose, резервные копии, инструкции
docker-compose.yml           запуск на своём компьютере со сборкой образов
docker-compose.release.yml   запуск из уже собранных образов (например, на компьютере друга)
.env.example                 образец настроек для docker-compose.yml
```

## Быстрый старт для разработки

Нужны Python 3.12, Node.js (LTS) и PostgreSQL.

### 1. База данных

Создайте пользователя и две базы: рабочую и тестовую (имя тестовой должно оканчиваться на `_test`, иначе тесты откажутся запускаться, чтобы не стереть рабочие данные):

```sql
CREATE USER nutrition WITH PASSWORD 'nutrition_pass';
CREATE DATABASE nutrition OWNER nutrition;
CREATE DATABASE nutrition_test OWNER nutrition;
```

### 2. Backend

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env          # откройте .env и задайте JWT_SECRET_KEY (команда для генерации указана в файле)
alembic upgrade head            # создать таблицы
uvicorn main:app --reload       # сервер на http://127.0.0.1:8000
```

Документация API и ручная проверка запросов: <http://127.0.0.1:8000/docs> (в режиме разработки включена).

Если пароль или имя базы другие, задайте `DATABASE_URL` в `backend/.env` (образец в `.env.example`).

### 3. Frontend

```powershell
cd frontend
copy .env.local.example .env.local
npm install
npm run dev                     # сайт на http://localhost:3000
```

### 4. Тесты

```powershell
cd backend
pytest -v                       # использует базу nutrition_test; другой адрес: переменная TEST_DATABASE_URL
```

```powershell
cd frontend
npx tsc --noEmit                # проверка типов
npm run lint
npm run build                   # полная сборка, как на сервере
```

## Запуск через Docker на своём компьютере

Нужен Docker Desktop.

```powershell
copy .env.example .env          # откройте .env и впишите POSTGRES_PASSWORD и JWT_SECRET_KEY
docker compose up -d --build
```

Сайт откроется на <http://localhost:3000>. База и фото хранятся в томах Docker и переживают перезапуск. Порты доступны только с этого же компьютера.

**Запуск у друга без исходного кода.** На своём компьютере соберите образы, сохраните их в файл и перенесите вместе с `docker-compose.release.yml` и `.env`:

```powershell
docker compose build
docker save -o lad-images.tar nutrition-backend:1.1 nutrition-frontend:1.1
```

На компьютере друга (установлен Docker Desktop):

```powershell
docker load -i lad-images.tar
docker compose -f docker-compose.release.yml up -d
```

Образы собираются под архитектуру вашего компьютера: если у друга Mac на процессоре Apple (ARM), а у вас Windows на обычном процессоре, соберите образы командой `docker buildx build --platform linux/arm64` или соберите их у друга.

## Публичный сервер

Полная инструкция: [deploy/README.md](deploy/README.md) (подготовка сервера, DNS, HTTPS, первый запуск, обновление и откат, чек-лист безопасности). Резервные копии и восстановление: [deploy/BACKUP.md](deploy/BACKUP.md).

Кратко: один домен, Caddy выдаёт сертификат и принимает трафик на портах 80 и 443; сайт и API открываются с одного адреса (`/api` — backend); база доступна только внутри закрытой сети Docker.

## Безопасность

- Токен доступа живёт 15 минут, сессия обновляется через HttpOnly-cookie на 30 дней с ротацией; смена пароля сразу завершает все старые сессии.
- Ограничения на число попыток входа и регистрации, проверка источника запроса, строгие заголовки (CSP, HSTS в боевом режиме, запрет встраивания в чужие страницы), ограничение размера запросов.
- При `ENVIRONMENT=production` приложение не запустится с слабым секретом, небезопасным CORS или без списка допустимых хостов; документация API закрыта.
- После того как вы и семья зарегистрировались, закройте регистрацию (`REGISTRATION_OPEN=false`).
- Секреты хранятся только в `.env` и в Git не попадают (см. `.gitignore`).

Ограничения первой версии перечислены в [CHANGELOG.md](CHANGELOG.md) и в разделе 13 файла `deploy/README.md`.

## Примечания

- Файлы `test_db.py` (проверка подключения к PostgreSQL) и `test_security.py` (проверка хеширования паролей) в корне — ранние ручные скрипты. Они не входят в набор автоматических тестов (тесты лежат в `backend/tests`, их запускает `pytest`) и работают только из папки `backend`, поэтому из корня они не запустятся. Их можно удалить или перенести в `backend/`.
- Если в `frontend/AGENTS.md` или в документации Next.js указаны отличия от привычных версий, ориентируйтесь на документацию в `frontend/node_modules/next/dist/docs/`.
