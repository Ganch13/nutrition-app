# Обновление работающего сервера с 1.0.0 до 1.1.0

Инструкция для сервера, на котором уже запущена версия 1.0.0 по [README.md](README.md) (вариант А: архив с компьютера по `scp`). Данные, сертификаты и `deploy/.env` при обновлении не пропадают: данные лежат в Docker-томах, а файл `.env` в архив не попадает.

## Что меняется в этой версии

- backend: новая миграция базы `7a1c3e5b9d20` (повторяющиеся доходы и платежи, режим бюджетного периода, финансовые цели, удаление аккаунта). Она применяется сама при старте backend (`alembic upgrade head` в `CMD` образа). Новые таблицы пустые, существующие данные не меняются.
- frontend: новый интерфейс, название «Лад», новые значки и заставки, шрифты внутри приложения (внешние сервисы не нужны).
- Образы Docker получили метку `1.1` (были `1.0`). Старые образы остаются на диске, пока вы их не удалите: это запас для отката.
- Новых настроек в `deploy/.env` нет. Ничего менять в нём не нужно.

Время: сборка на сервере с 1 ядром и 2 ГБ памяти занимает 8–15 минут (образы собираются по одному, сайт всё это время работает). Недоступен сайт только в момент перезапуска, около минуты.

## Порядок действий

### 1. На сервере: резервная копия и снимок старого кода

Подключитесь: `ssh deploy@IP-СЕРВЕРА`. Затем:

```bash
cd ~/nutrition
docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env exec -T backup bash /backup/backup.sh
ls -lh /var/backups/nutrition | tail -4        # свежие файлы nutrition-db-... и nutrition-photos-...
cp -a ~/nutrition ~/nutrition-1.0              # снимок старого кода вместе с deploy/.env (нужен для отката)
```

Что делают команды: первая просит службу `backup` сделать копию базы и фото прямо сейчас; вторая показывает, что файлы появились (должны быть с сегодняшней датой); третья копирует папку с кодом целиком: если что-то пойдёт не так, вы вернёте прежнюю версию.

`deploy.sh` ещё раз сделает копию перед пересборкой, но своя копия «до начала» надёжнее.

### 2. На компьютере: упаковать проект

В PowerShell на Windows (путь замените на папку вашего проекта):

```powershell
cd C:\Users\user\PycharmProjects\nutrition-app
tar -czf $env:TEMP\nutrition.tar.gz '--exclude=node_modules' '--exclude=.venv' '--exclude=.next' '--exclude=.git' '--exclude=.idea' '--exclude=__pycache__' '--exclude=.pytest_cache' '--exclude=.env' '--exclude=.env.local' '--exclude=uploads' '--exclude=*.dump' '--exclude=*.tar' '--exclude=*.tar.gz' .
(Get-Item $env:TEMP\nutrition.tar.gz).Length / 1MB
scp $env:TEMP\nutrition.tar.gz deploy@IP-СЕРВЕРА:~/
```

Это те же команды, что при первом запуске. Вторая строка показывает размер архива: должно быть около 2 МБ (без `node_modules` и `.venv` проект маленький); больше 50 означает, что в архив попало лишнее.

### 3. На сервере: распаковать поверх и убрать устаревшие файлы

```bash
cd ~
tar -xzf ~/nutrition.tar.gz -C ~/nutrition && rm ~/nutrition.tar.gz
cd ~/nutrition
rm -f frontend/app/apple-icon.tsx
rm -rf frontend/app/pwa-icon
chmod +x deploy/*.sh deploy/backup/*.sh
```

Что делают команды: распаковка заменяет файлы новыми, но **не удаляет** файлы, которых в новой версии больше нет. Два таких файла нужно убрать руками: старые генераторы значка (`frontend/app/apple-icon.tsx` и папка `frontend/app/pwa-icon`). Если оставить, они конфликтуют с новыми файлами значков (`apple-icon.png`, `public/icons/`) и сборка frontend может завершиться ошибкой. `chmod` возвращает право запуска скриптам.

### 4. Проверить, что вы не потеряли свои правки на сервере

Распаковка перезаписывает файлы. Если вы когда-либо правили на сервере `deploy/Caddyfile`, `deploy/docker-compose.prod.yml` или другие файлы, сравните со снимком:

```bash
diff -r ~/nutrition-1.0/deploy ~/nutrition/deploy | head -60
```

Ожидаемая разница: в `docker-compose.prod.yml` две строки `image: ...:1.0` → `...:1.1`, в `README.md` и `BACKUP.md` текст, в `UPDATE.md` новый файл. Если видите другие отличия в `Caddyfile` или скриптах, которые вы делали сами, перенесите свои правки в новые файлы вручную (`nano deploy/Caddyfile`).

`deploy/.env` проверять через `diff` не нужно: его нет в архиве, он остался как был. Проверьте, что он на месте и настройки в порядке:

```bash
ls -l deploy/.env                  # должен быть, права -rw------- (600)
./deploy/check-env.sh              # ожидается: Настройки в порядке
```

### 5. На сервере: запустить обновление

```bash
./deploy/deploy.sh
```

Что делает скрипт (тот же, что при первом запуске): проверяет настройки, делает резервную копию, собирает образ backend, затем образ frontend, запускает службы и ждёт, пока они станут здоровыми. Миграция базы применится при старте backend.

Ожидаемый результат: таблица служб, где `db`, `backend`, `frontend`, `caddy`, `backup` в состоянии `running` / `healthy`, и внизу строка `Готово. Сайт: https://ваш-домен`.

Если сборка завершилась словом `Killed`, не хватило памяти: проверьте файл подкачки (`free -h`, раздел 2.6 в README) и повторите `./deploy/deploy.sh`: кэш сборки сохранится.

### 6. Проверить, что запустилась новая версия

```bash
docker images | grep nutrition                      # теги 1.1 (и старые 1.0 рядом)
docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env exec backend alembic current
```

Ожидаемый результат второй команды: `7a1c3e5b9d20 (head)`.

С вашего компьютера (домен замените на свой):

| Проверка | Команда | Ожидаемый результат |
| --- | --- | --- |
| API жив | `curl -s https://ВАШ-ДОМЕН/api/health` | `{"status":"ok"}` |
| Новые финансовые эндпоинты есть и закрыты входом | `curl -s -o /dev/null -w "%{http_code}\n" https://ВАШ-ДОМЕН/api/finance/ledgers/1/goals` | `401` |
| Удаление аккаунта есть и закрыто входом | `curl -s -o /dev/null -w "%{http_code}\n" https://ВАШ-ДОМЕН/api/auth/delete-account/preview` | `401` |
| Документация по-прежнему закрыта | `curl -s -o /dev/null -w "%{http_code}\n" https://ВАШ-ДОМЕН/api/docs` | `404` |
| Заставка и значок отдаются | `curl -sI https://ВАШ-ДОМЕН/icons/icon-512.png` | `200`, `content-type: image/png` |

### 7. Проверить в браузере

Откройте сайт, нажмите Ctrl+F5 (чтобы подтянулись новые файлы), затем пройдите по списку.

1. Вкладка называется «Лад: питание, тренировки и деньги семьи», на странице входа видно «Лад» и «глаз» справа в поле пароля.
2. Регистрация: два поля пароля, при несовпадении красная подсказка «Пароли не совпадают».
3. Войдите своим аккаунтом: главная открывается, в меню слева группы «Сегодня», «Еда», «Тело», «Дом».
4. «Финансы → Платежи и доходы»: добавьте зарплату (отметьте «Начинает новый период») и пару обязательных платежей. «Финансы → Обзор»: появилась лента периода и сумма «можно тратить в день».
5. «Финансы → Настройки»: переключите период на «От дохода до дохода».
6. «Финансы → Цели»: создайте накопление и убедитесь, что оно видно в списке.
7. Проверка удаления аккаунта **только на тестовом аккаунте**: создайте новый аккаунт (если вы закрыли регистрацию через `REGISTRATION_OPEN=false`, откройте её на время по разделу 8 README), «Профиль → Удалить аккаунт», введите пароль. Ожидаемый результат: переход на страницу входа с сообщением об удалении. Повторный вход этим email невозможен.

### 8. На телефоне

- **iPhone:** название, значок и заставку iPhone запоминает при установке, поэтому старый значок нужно удалить (нажмите и удерживайте значок → «Удалить закладку»), затем открыть сайт в Safari и снова «Поделиться → На экран „Домой“». После этого при запуске появляется светлая заставка с буквой «Л» вместо чёрного экрана.
- **Android:** Chrome обновит название и значок сам в течение суток; чтобы увидеть сразу, удалите приложение и установите снова.
- Если на телефоне видно старый интерфейс: закройте приложение полностью (смахните из списка) и откройте снова. Service worker сам удаляет старые кэши `balance-*`.

### 9. Если сайт стоит за Cloudflare

Cloudflare по умолчанию кэширует картинки, стили и скрипты. Чтобы новые файлы дошли сразу, после обновления откройте Cloudflare → Caching → Configuration → **Purge Everything**. Это безопасно: кэш просто наполнится заново.

### 10. Уборка (через неделю, когда убедитесь, что всё работает)

```bash
docker image rm nutrition-backend:1.0 nutrition-frontend:1.0     # старые образы (запас для отката)
docker image prune -f                                            # недособранные слои
docker builder prune -f                                          # кэш сборки
rm -rf ~/nutrition-1.0                                           # снимок старого кода
df -h /                                                          # сколько места осталось
```

## Откат

Если после обновления что-то не работает и починить быстро не получается:

```bash
cd ~
mv nutrition nutrition-1.1-broken
mv nutrition-1.0 nutrition
cd nutrition
./deploy/deploy.sh
```

Это возвращает код версии 1.0.0 (в нём `deploy/.env` и образы с меткой `1.0`). Но база уже могла получить миграцию 1.1.0, а код 1.0.0 про неё не знает. Поэтому после возврата кода восстановите базу из копии, сделанной в шаге 1 (она не содержит новых таблиц):

```bash
ls -lh /var/backups/nutrition | tail -6          # выберите файлы, сделанные в шаге 1
./deploy/backup/restore.sh /var/backups/nutrition/nutrition-db-ДАТА_ВРЕМЯ.dump \
                           /var/backups/nutrition/nutrition-photos-ДАТА_ВРЕМЯ.tar.gz
```

Скрипт спросит слово `ВОССТАНОВИТЬ` и не удаляет текущую базу, а переименовывает её (подробности в [BACKUP.md](BACKUP.md), раздел 5). Данные, внесённые после копии (за время работы 1.1.0), при этом теряются.

## Какие файлы нужно менять на сервере руками

| Файл | Нужно ли менять |
| --- | --- |
| `deploy/.env` | **Нет.** Новых настроек в версии 1.1.0 нет |
| `deploy/Caddyfile`, `deploy/docker-compose.prod.yml` | Нет, приходят с архивом; сверьте с прежними правками (шаг 4) |
| `frontend/app/apple-icon.tsx`, папка `frontend/app/pwa-icon` | **Удалить** (шаг 3): распаковка архива не удаляет файлы |
| Скрипты `deploy/*.sh`, `deploy/backup/*.sh` | Только выдать право запуска (`chmod +x`, шаг 3) |

## Если что-то не работает

| Симптом | Причина и решение |
| --- | --- |
| `./deploy/deploy.sh: bad interpreter` или `\r: command not found` | Скрипты приехали с Windows-переводами строк. Выполните `sed -i 's/\r$//' deploy/*.sh deploy/backup/*.sh` и повторите |
| Сборка frontend: ошибка про конфликт `apple-icon` | Не удалены старые файлы из шага 3 |
| `backend` перезапускается, в `docker compose ... logs backend` ошибка `alembic` | Покажите последние 40 строк журнала. Не запускайте `alembic` вручную: сначала сделайте откат |
| Сайт открывается, но на телефоне вечная «Загрузка...» | Закройте приложение и откройте снова; если повторяется только в мобильной сети, а по Wi-Fi работает, дело в сети оператора, а не в версии |
| Старое название «Balance» на экране телефона | iPhone хранит имя с момента установки: удалите значок и установите приложение заново (шаг 8) |
