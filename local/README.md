# Локальная проверка перед выкладкой

Каждая доработка сначала собирается в локальный контейнер и проверяется на этом компьютере в Docker Desktop. На сервер выкладываем только после проверки.

Порядок работы:
1. Изменения вносятся в код.
2. `.\local\lad-local.cmd up`: собирается локальный контейнер из текущего кода.
3. Вы проверяете пункты из раздела «Что проверить» ниже.
4. Если всё хорошо, выкладываем на сервер (`deploy/UPDATE.md`). Если нет, дорабатываем и снова выполняем `up`.

## Что это за окружение

| | Локальная проверка | Боевой сервер |
| --- | --- | --- |
| Группа в Docker Desktop | `lad-local` | (на сервере) `nutrition-prod` |
| Контейнеры | `lad-local-1.3.0-db`, `lad-local-1.3.0-backend`, `lad-local-1.3.0-frontend` | — |
| Образы | `lad-backend:1.3.0-local`, `lad-frontend:1.3.0-local` | `nutrition-*:1.x` |
| Настройки | `local/.env` (создаётся сам, случайные ключи) | `deploy/.env` на сервере |
| База | том `lad-local_db`, база `lad_local` | боевая база на сервере |
| Адрес | http://localhost:3100, API http://localhost:8100/docs | домен |

`1.3.0` в именах — это версия, которая сейчас проверяется. Если в Docker Desktop видна группа `lad-local` с контейнерами `lad-local-1.3.0-*`, значит запущена именно локальная проверка этой версии.

Окружение не трогает сервер: в нём нет адреса сервера, ключей и `deploy/.env`. Порты другие, поэтому оно не мешает разработке на 3000/8000 (`npm run dev`, `uvicorn`).

## Команды

Все команды выполняются на вашем компьютере в PowerShell из папки проекта `C:\Users\user\PycharmProjects\nutrition-app`. Docker Desktop должен быть запущен.

Файл `.cmd` — обёртка над `lad-local.ps1`: она запускает скрипт в обход блокировки ExecutionPolicy только для этого вызова.

| Команда | Что делает | Что будет после |
| --- | --- | --- |
| `.\local\lad-local.cmd up` | Собирает образы из текущего кода, применяет миграции, запускает и ждёт статуса healthy | «Готово. Приложение: http://localhost:3100». Первая сборка 3–5 минут, следующие быстрее |
| `.\local\lad-local.cmd up -Seed` | То же, плюс демо-данные | «Готово. Вход: demo@example.com…» |
| `.\local\lad-local.cmd seed` | Демо-данные в уже запущенное окружение | Повторный запуск ничего не дублирует: «Демо-данные уже есть» |
| `.\local\lad-local.cmd reset` | Стирает локальную базу и фото, запускает с чистого листа | Пустая база, регистрируйтесь заново или добавьте `-Seed` |
| `.\local\lad-local.cmd status` | Состояние контейнеров | Три строки со статусом `(healthy)` |
| `.\local\lad-local.cmd logs backend` | Журнал сервиса (`backend`, `frontend`, `db`), Ctrl+C — выход | Строки журнала |
| `.\local\lad-local.cmd down` | Останавливает, данные сохраняются | Контейнеры остановлены |
| `.\local\lad-local.cmd purge` | Полная очистка: контейнеры, тома, образы `*-local`, `local/.env` | В Docker Desktop группы `lad-local` больше нет |

- [ ] Главная, «Личные»: «Всего» = **70 631 ₽**. Две прошлые зарплаты не подтверждены и не входят, аренда ещё не оплачена и тоже не входит. Подписка 299 с автосписанием входит.
- [ ] «Финансы» → «Платежи и доходы»: добавить доход на вчера и платёж без автосписания на прошлую неделю → «Всего» на главной **не изменилось**.
- [ ] Подтвердить доход в окне «Поступил ли платёж?» → «Всего» выросло на эту сумму.
- [ ] «Изменить баланс» → ввести `65000` → подсказка «Корректировка: −5 631 ₽» (если «Всего» было 70 631) → «Сохранить» → «Всего» = 65 000 ₽.
- [ ] «Финансы» → «Операции»: доходы и расходы за месяц после корректировки **не изменились**.
- [ ] В окне «Изменить баланс» → «Отменить» у корректировки → «Всего» вернулось.
- [ ] То же в разрезе «Семья» (семейная книга считается отдельно, 57 800 ₽).

#### Правка шага 2: «Баланс», «Свободно» и «Можно тратить в день» из одного расчёта
Формулы: свободно = баланс − неоплаченные обязательные платежи с сегодня до дня перед следующим основным доходом; в день = свободно ÷ дни до этого дохода. Ожидаемый доход не входит, пока его не подтвердят.
- [ ] Главная, «Личные»: подпись **«Баланс»** (не «Всего») = 70 631 ₽. «Свободно до 5 нояб.» = **35 332 ₽** (70 631 − аренда 35 000 − подписка 299).
- [ ] «Финансы» → «Обзор»: «Можно тратить в день» = **5 047,43 ₽**, «до 5 нояб., 7 дней». Плитка «Останется» = 35 332 ₽, те же цифры, что на главной.
- [ ] Семья: «Баланс» 57 800 ₽, «Свободно до 10 нояб.» 57 800 ₽.
- [ ] Случай из ТЗ: `reset`, зарегистрировать нового пользователя, включить финансы, добавить основной доход 70 000 на ближайшие дни и ничего не подтверждать. «Баланс» 0, «Свободно» 0, «Можно тратить в день» 0 ₽ (а не 23 333).
- [ ] Без основного дохода вместо числа текст «Нет следующего дохода: укажите дату…». Если платежей больше, чем денег: «Не хватает N ₽», метка красная «Не хватает денег».

### Шаг 4. Плохая сеть и недоступный сервер (пункт 3)
Пересборка: `.\local\lad-local.cmd up`. Проверять в Chrome на http://localhost:3100 после входа. Service worker работает только в собранной версии, то есть в этом контейнере, а не в `npm run dev`. Если раньше открывали старую версию, один раз обновите страницу (Ctrl+F5): в DevTools → Application → Service Workers должна быть активна новая `sw.js` (версия кэша `lad-…-v4`).
- [ ] **Медленная сеть.** DevTools → Network → «Slow 4G» или «3G» → обновить страницу. Виден светлый экран с иконкой и полосой загрузки («Загружаем ваши данные»), а не белый или чёрный. Через 8 с «Связь медленная» и «Повторить».
- [ ] **Тайм-аут.** Network → свой профиль скорости (Add custom profile: Latency 25000 ms) → обновить. Загрузка не бесконечная: не позже чем через ~30 с вместо индикатора «Сервер недоступен, попробуйте позже» и «Повторить».
- [ ] **Нет интернета у устройства.** Network → «Offline» → обновить страницу → «Нет подключения к интернету» (страница из кэша service worker). Снять «Offline» → страница сама перезагружается в приложение.
- [ ] **Выключен сервер API.** `docker stop lad-local-1.3.0-backend` → обновить → «Сервер недоступен, попробуйте позже» и «Повторить». `docker start lad-local-1.3.0-backend` → «Повторить» → приложение открылось.
- [ ] **Выключен весь сервер** (как при закончившейся аренде). `docker stop lad-local-1.3.0-frontend lad-local-1.3.0-backend` → обновить → страница «Сервер недоступен, попробуйте позже» из кэша, а не ошибка браузера. Затем `docker start lad-local-1.3.0-backend lad-local-1.3.0-frontend` → «Повторить».
- [ ] Переход между разделами при медленной сети: меню на месте, в содержимом «Открываем раздел...».

### Шаг 6. Сводные расходы за период (пункт 5)
Пересборка: `.\local\lad-local.cmd reset -Seed`. «Финансы» → «Операции» → переключатель **«Сводка за период»**.
- [ ] Период «Неделя» (текущая неделя, конец не позже сегодня), строки «Продукты 8 000» и «Транспорт 1 200», «Итого 9 200 ₽» → «Сохранить сводку». В демо-данных за эти дни уже есть покупки, поэтому открывается окно **«Это дополнение или повтор?»** с текстом «уже записано … сводка на 9 200 ₽», списком покупок и тремя кнопками.
- [ ] «Отмена» → ничего не сохранилось, операции и баланс прежние.
- [ ] «Это повтор, заменить» → показанные покупки «Продукты» и «Транспорт» удалены, вместо них две строки с подписью «Сводка …». Покупки других категорий (кино, аптека и т. д.) на месте. Баланс = прежний + удалённое − 9 200.
- [ ] Та же сводка ещё раз → окно показывает «прежняя сводка» → «Добавить как дополнение» → ничего не удалилось, добавились ещё две строки.
- [ ] Удалить строку сводки → «Удалить всю сводку» → баланс вернулся.
- [ ] Период «День» и «Месяц», «Свои даты»: подсказка под датой показывает период. Месяц текущий заканчивается сегодня.
- [ ] Строка сводки с целью «Отпуск» → в цели сумма выросла. Удаление сводки откатывает цель.
- [ ] Сводка за период без покупок сохраняется сразу, без окна.
